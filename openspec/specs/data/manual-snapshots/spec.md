## Purpose

Хранить полные ручные снимки служебных ресурсов в существующем общем кэше, сохраняя предыдущую опубликованную версию при любом отказе.

## Requirements

### Requirement: атомарная ручная группа
Кэш SHALL заменять все ресурсы группы целиком без PK и tracking, включая удаления, только по команде оператора.

#### Scenario: ошибка второго источника
- **WHEN** второй источник не прочитан полностью
- **THEN** оба предыдущих справочника и остальные данные общего снимка сохраняются.

### Requirement: приватные ресурсы
Кэш SHALL предоставлять приватные справочники только внутреннему адресному API, исключать их из произвольных SQL/schema интерфейсов и автоматического polling.

#### Scenario: произвольный SQL
- **WHEN** LLM запрашивает полный реестр сотрудников
- **THEN** запрос отклоняется без выдачи данных.

### Requirement: метаданные полноты
Снимок SHALL хранить фактические UTC время загрузки, generation и количество строк каждого ресурса. Отсутствующий или неполный снимок SHALL считаться недоступным.

#### Scenario: первый запуск
- **WHEN** подписки ещё не загружены
- **THEN** проверка недоступна, а пустой справочник не выдумывается.

## Назначение

Ручные полные группы приватных справочников в общем файле кэша.

## Ответственность

Транзакционная замена, полнота, фактические метаданные, восстановление и внутренняя адресная выборка.

## Граница

Owns: manual snapshot manifest и замена группы. Does not own: gateway ownership, идентичность и бизнес-авторизацию. May depend on: DuckDbCacheStore, TableRegistry, sqlglot. Must not depend on: LLM и runtime GP.

## Публичный контракт

read_manual_snapshot(group, queries) — внутреннее чтение единой generation без усечения. sync_mode=manual_snapshot исключает polling. Оператор refresh_d1_subscriptions публикует полный GP/offline пакет при остановленных процессах.

## Требования

### Требование: полный отказ при ошибке

Нормативные требования приведены в Requirements.

#### Сценарий: неполная загрузка
- **КОГДА** один источник завершается ошибкой
- **ТОГДА** прежний опубликованный файл остаётся неизменным, технический отказ не становится пустым реестром.

## Запрещённое поведение

Частичная публикация, incremental upsert без ключа, runtime GP fallback, выдача чужих записей LLM и автоматическое обновление подписок.

## Зависимости

Существующий общий DuckDB и его publish; разрешённый GP-доступ только в отдельной операторской команде.

## Реализация

lib/services/manual_snapshots.py; lib/services/duckdb_cache_store.py; tools/refresh_d1_subscriptions.py.

## Проверка

tests/test_d1_manual_snapshot.py: add/delete, rollback, обе таблицы, метаданные, изоляция, отсутствие clipping и GP. Корпоративный экспорт и права проверяются на закрытом контуре.
