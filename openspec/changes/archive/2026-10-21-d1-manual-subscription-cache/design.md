## Context

См. proposal.md. Старый store D1 открывается через constructor/open; finalize использует concrete factory и ownership. Их общие файлы нельзя заменять целиком.

## Goals / Non-Goals

Согласованная пара справочников в общем снимке, без GP в диалоге. Не менять OSIRIS, KB polling, интервалы sync и бизнес-SQL.

## Decisions

- TableResource.sync_mode=manual_snapshot исключает ресурс из polling без фиктивной tracking-колонки. label исключает его из skill schema.
- Общие manual snapshot helpers хранят generation, UTC timestamp и row counts в __nanobot_meta; store публикует metadata вместе с данными. При открытии owner восстанавливает только ручные ресурсы из предыдущего опубликованного файла, без удержания файла открытым.
- Внутренний read_manual_snapshot держит lock при проверке полноты и двух адресных запросах. fetchall исключает max_rows clipping. Общедоступные query/schema API блокируют приватные ресурсы и динамические table scans.
- Оператор останавливает gateway, передаёт --gateway-stopped; загрузчик под локальным lock копирует все данные существующего снимка в staging common store, заменяет группу транзакционно и вызывает штатный publish. Проверка fingerprint до публикации отвергает конкурентное изменение файла. Предыдущий файл сохраняется при отказе.
- GP режим использует один read-only repeatable-read snapshot с серверными курсорами. Офлайн-пакет содержит обе полные таблицы, expected row counts и SHA256; частичный пакет отклоняется. Фактическое время загрузки хранится отдельно от source timestamp.

## Risks / Trade-offs

Ручная актуализация допускает устаревшие добавления и отзывы: D1 не является системой авторизации. Требуется остановка всех owner-процессов и защита файла на уровне ОС. Неверно подготовленный, но самосогласованный офлайн-пакет требует доверия оператору; приложение не подтверждает его бизнес-полноту.
