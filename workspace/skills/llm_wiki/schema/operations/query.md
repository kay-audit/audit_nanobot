# Операция query

## Цель

Ответить только на основании Wiki и первоисточников. Query ничего не изменяет и
не сохраняет автоматически.

## Обязательное чтение

1. `AGENTS.md`;
2. этот файл;
3. `wiki/index.md`.

## Поиск

1. Разложи вопрос на информационные потребности.
2. Выполни локальный семантический поиск FAISS по `wiki/pages/` и производным
   Jira/Confluence-карточкам. Для карточек индексируются title, ID, тип и
   подробное summary, но не огромный оригинал.
3. Используй найденные страницы как стартовые независимо от того, перечислены
   ли они непосредственно в `wiki/index.md`.
4. Расширь выборку по релевантным Wiki-ссылкам; по умолчанию используй не более
   трёх переходов.
5. Всегда добавляй `wiki/index.md` в передаваемый контекст как карту базы, но не
   используй его как единственные поисковые ворота.
6. Веди список просмотренных файлов, не ходи циклически.
7. Переходи только по ссылкам, полезным для ответа.
8. Не читай всю Wiki «на всякий случай».
9. Если FAISS недоступен или устарел, остановись с явной ошибкой и потребуй
   перестроить индекс; не скрывай переход на другой механизм. Режим `lexical`
   допустим только как явно выбранная диагностическая настройка.
10. Если найдена Jira/Confluence-карточка, сделай не более одного перехода по
    явной связи Jira↔Confluence. Каждый выбранный документ прочитай отдельным
    вызовом LLM; не помещай все большие Confluence в один запрос.
11. Для вопроса о багах Confluence может определять смысл темы, но сведения о
    самих багах, их типах и статусах подтверждай Jira. Для кодов ошибок и
    технических условий используй соответствующий Confluence.

## Проверка происхождения

1. Для ключевых фактов найди карточки источников.
2. Для чисел, точных, спорных или изменчивых сведений проверь оригинал.
3. Не подменяй первоисточник summary карточки.
4. При неполном чтении снизь уверенность.
5. Не путай отсутствие данных с доказательством отсутствия явления.

При конфликте изложи каждый вариант, источник, возможные разные условия и то,
что нужно для разрешения.

## Формат ответа

```markdown
## Краткий вывод

Прямой ответ.

## Подробный ответ

Обоснование и условия.

## Связанные темы

- [[Название страницы]] — смысл связи.

## Ограничения

- Область применимости и ограничения источников.

## Противоречия и неопределённости

- Варианты, источники и необходимая проверка.

## Использованные Wiki-страницы

- [[Название страницы]]

## Использованные первоисточники

- [[Карточка]] — `raw/sources/file.ext`

## Достаточность информации

Оценка: достаточная / частичная / недостаточная.
```

`достаточная` означает прямое покрытие вопроса; `частичная` — заметные пробелы;
`недостаточная` — прямых данных нет или конфликт мешает выводу.

Query не сохраняется внутри Wiki. По явной опции
`save_markdown=True` или `--save-markdown` контроллер может сохранить
копию ответа в `reports/query/`; это не изменяет `wiki/` и не считается
первоисточником. Если пользователь хочет интегрировать новое
знание, он добавляет подходящий первоисточник и запускает отдельный `ingest`;
ответ query не является первоисточником.

Программный query сначала локально выбирает страницы через FAISS, расширяет
контекст по Wiki-ссылкам и только затем передаёт модели выбранные страницы,
карточки и фрагменты. Модель не получает файловых инструментов. Построение
индекса выполняется отдельной локальной командой и не является query.

## Запреты

- Не изменяй файлы.
- Не добавляй знания модели.
- Не скрывай нехватку данных.
- Не перечисляй неиспользованный источник.
- Не выдавай Proposal или lint за доказательство факта.
