# LLM-Wiki

Используй инструмент `llm_wiki`, не подменяй его собственным пересказом.

- `action=query, question=...` — ответы по имеющейся базе, например «Расскажи о DEMO-1001». Wiki не изменяется.
- `action=status` — проверка конфигурации и индекса без вызова MiniMax.
- `action=prepare` — обработать добавленные администратором JSON и обновить производную базу поиска.
- `action=load, key=DEMO-1001` или `key=DEMO` — подготовить выбранную задачу или проект из локальных JSON.
- `dry_run=true` с query — проверить выбор контекста без вызова LLM.

Prepare/load вызывай только по явному запросу пользователя на обновление базы.
Они не скачивают JSON из Jira: администратор размещает выгрузки в
`workspace/skills/llm_wiki/raw/sources/`.
Пустая папка, устаревший индекс и ошибки API — сообщить пользователю;
не запускать бесконечные повторные попытки.

Ответ возвращается JSON: `status=ok, action, result`.
Для query текст ответа находится в `result.answer`, использованные документы —
в `result.selected_paths`. Показывай ограничения и ссылки на источники.
При `status=error` объясни `error_type` и `message`, не выдавай ошибку за ответ.

Индекс и карточки сохраняются внутри каталога этого навыка. MiniMax и BGE-M3
остаются компонентами LLM-Wiki; общие модели/БД nanobot не заменяются.
Ключ MINIMAX_API_KEY наследуется из окружения nanobot. Не проси ключ в чате,
не передавай его аргументом инструмента, не сохраняй в файлы.

Этот инструмент не предоставляет ingest/apply. Тематические Wiki-изменения
выполняются отдельно через штатный CLI LLM-Wiki: Proposal и явное подтверждение.
