# Контракт исполнения IOR

## Запросы и отчёты

Внешний API остаётся `prompt` и необязательный `preset`. Единый детерминированный
`RequestPlan` задаёт предмет анализа, независимые категории фильтров, список
полуоткрытых интервалов времени и Decimal-условия суммы. Этот же план передаётся
в LLM-контекст. Пользовательские ограничения не являются найденными аномалиями.

Происхождение: `org_struct_lvl_3_name`; ответственность: `funct_block_lvl_3_name`.
Уровень 4 не участвует в организационной принадлежности. Совпадающее название
в двух категориях требует бизнес-уточнения до запросов, файлов и LLM. Ответ
добавляется к исходному запросу как `Уточнение: ...`. Неизвестный явный фильтр,
неразобранная сумма/период и конфликт предметов не разрешают широкую выгрузку.
SBR-коды не поддерживаются; физические префиксы области ПАО сохранены.

Несколько DRP одной категории — OR, самостоятельные категории — AND. Кварталы
Q1 и Q3 образуют два интервала; Q1–Q3 — один. Отдельные срезы выводятся внутри
одного отчёта без дополнительных выгрузок. Финансовые суммы фильтруются по
financial impact, суммы возмещения — по recovery. Конкретные виды потерь в чате
направляются в специальную вкладку; canonical structured input сохраняется.

Автоматического ограничения 100000 строк и подменяющего его лимита нет.
Запросы пресетов используют явную проекцию основных предметных полей.
SQL LIMIT возможен только при явном положительном параметре внутренних tools.
NULL денежных полей сохраняется пустым; настоящий ноль остаётся числом 0.
Удалённый ИОР без строки журнала сохраняется, но не считается действием удаления.

Гипотезы не формируются при менее 50 уникальных incdnt_sid. JOIN-строки не
увеличивают число ИОР. Досье никогда не генерирует гипотезы.

## OSIRIS: перенос из d3_nanobot

Без изменений перенесён пакет `workspace/utils/osiris_runtime`: `__init__.py`,
`client.py`, `config.py`, `errors.py`, `lifecycle.py`, `worker.py`. Общие
`ServiceProfile`, `ensure_ready`, `request`, NFS-манифесты protocol_version=2,
heartbeat, SDK lifecycle, захват очереди и recovery используются напрямую.
Нового transport/lifecycle вместо существующего механизма нет.

IOR-адаптеры: `utils/osiris_config.py`, `utils/osiris_client.py` и отдельный
`rerank_osiris_worker.py`. Профиль service=ior, job=srbd6, pool=common, один GPU.
В gateway остаются только подготовка данных, идентичность extract/index и
валидация ответов. CUDA-модели BGE и reranker, FAISS, BM25 и RRF работают в worker.
`utils/osiris_search_runtime.py` сохраняет прежний глобальный поисковый алгоритм.
CPU-fallback для моделей отсутствует.

Закрытый контур должен предоставить OSIRIS SDK, CUDA image с torch,
sentence-transformers, faiss и зависимостями существующего BGE pipeline,
доступные локальные модели и единый NFS, видимый gateway и worker по одним путям.
Переопределения: IOR_OSIRIS_JOB_NAME, IOR_OSIRIS_IMAGE, IOR_OSIRIS_POOL,
IOR_OSIRIS_WORKER_SCRIPT, IOR_OSIRIS_NFS_ROOT. Таймауты берутся из общих
OSIRIS_* параметров `common_timeout_settings`, как в d3.

Последняя выгрузка получает version; её замена сначала инвалидирует индекс.
build/search/rerank проверяют version и допустимые EVE-ID. Никакая ошибка не
восстанавливает старый индекс. При рестарте worker требуется новая регистрация
индекса; пользователю возвращается понятное сообщение о недоступном поиске.

## Данные и проверка

Production-контракт Nanobot DuckDB Cache сохранён. `project.json`, конфигурация,
cache-provider, registration и backend factory не изменены. Автоматического
Greenplum fallback нет. Явные отладочные backend остаются прежними.

`test_business_contract.py` проверяет фактическую популяцию на DuckDB fixtures,
clarification без побочных эффектов, Decimal, периоды, slices, уникальные ИОР,
NULL/0, LEFT JOIN gaps и объёмы свыше 100000. `test_osiris_contract.py` проверяет
реальный общий NFS protocol с mock-моделями: embed, build, search, rerank,
identity, invalidation, malformed responses, correlation и timeout cleanup.
Обновлены старые проверки под новый бизнес-контракт. Интеграционный запуск
на закрытых данных и реальном OSIRIS остаётся обязательной проверкой при
развёртывании: локальные тесты не подтверждают доступность кластера.
