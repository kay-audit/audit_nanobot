# Таксономия LLM-Wiki

Все тематические страницы находятся в `wiki/pages/`. Основной тип задаётся
полем `category`, дополнительные аспекты — `tags`. Список расширяемый, но новая
категория добавляется только через Proposal, когда несколько реальных страниц
образуют устойчивый новый тип.

## Front matter тематической страницы

```yaml
---
title: Уникальное название
category: concepts
aliases: []
tags: []
status: active
updated_at: 2026-07-23
---
```

- `title` — уникальное название и цель Wiki-ссылки.
- `category` — одна категория из таблицы.
- `aliases` — реальные альтернативные названия.
- `tags` — дополнительные устойчивые темы.
- `status` — состояние содержимого.
- `updated_at` — дата содержательного изменения `YYYY-MM-DD`.

Не добавляй технические ID и slug. Имя файла должно совпадать с `title`, кроме
символов, недопустимых файловой системой.

## Категории

| Категория | Использование |
|---|---|
| `concepts` | Понятие, принцип, метод или термин |
| `entities` | Организация, проект, стандарт или именованная сущность |
| `technologies` | Инструмент, платформа, библиотека или протокол |
| `models` | Конкретная ML/LLM-модель или семейство |
| `infrastructure` | Вычислительная, сетевая или эксплуатационная среда |
| `launch_methods` | Способ запуска или развёртывания |
| `use_cases` | Пользовательский сценарий применения |
| `guides` | Практическая последовательность действий |
| `requirements` | Самостоятельный набор требований или критериев |
| `risks` | Риски, угрозы или меры снижения |

`sources` используется только карточками в `wiki/sources/`.

## Выбор категории

1. Сформулируй главный вопрос страницы.
2. Выбери одну категорию по главной функции.
3. Остальные аспекты укажи тегами и ссылками.
4. Не меняй категорию из-за одного нового раздела.
5. Не создавай новую категорию для одной страницы.

## Статусы страниц

- `active` — рабочая подтверждённая страница;
- `draft` — данных или проверки недостаточно;
- `deprecated` — тема устарела, но сохранена для истории.

## Карточки источников

```yaml
---
title: Уникальное название источника
category: sources
source_path: raw/sources/document.pdf
status: processed
updated_at: 2026-07-23
---
```

Статусы:

- `unprocessed` — оригинал зарегистрирован;
- `partial` — обработан не полностью;
- `processed` — согласованный объём интегрирован;
- `superseded` — есть новая версия, старая сохранена.

`source_path` всегда ведёт к оригиналу, не к `raw/extracted/`.

## Теги и названия

- Используй короткие устойчивые теги в нижнем регистре.
- Перед новым тегом ищи существующее написание.
- Не дублируй категорию тегом.
- Не используй теги вместо Wiki-ссылок.
- Выбирай распространённое однозначное название.
- Сохраняй официальное написание продукта.
- Если один термин означает разные сущности, уточни названия контекстом.

## Физическая структура

Разделение `wiki/pages/` допустимо позднее, если появились устойчивые крупные
группы, текущий каталог мешает работе, подготовлена карта перемещений и
пользователь подтвердил массовое изменение. Новая категория сама по себе не
требует новой папки.
